| 2026-09-02 | **Single-GPU placement — the app pins Ollama and the reranker to one card each.** Splitting a model's layers across GPUs buys capacity, not speed: the cards run sequentially and every token pays a cross-device hop (llama.cpp on this box: 94 → 170 tok/s once pinned). Both local runtimes were splitting. New `src/gpu_placement.py` holds the policy — `gpus()` (nvidia-smi), `plan(required_gib, mode)` (pin to the emptiest card that fits with 1 GiB headroom, else leave it split), `cuda_env(index)`. New `src/ollama_server.py` starts a **second `ollama serve`** on `OLLAMA_PIN_PORT` (11435) against the same model store, pinned, with `OLLAMA_NUM_PARALLEL=1`; the system daemon on `:11434` is left alone because it runs as `User=ollama` (its env needs root) and the box's other four Streamlit apps depend on it. `ollama_client.host()` is now the single way to reach Ollama — `agent`, `chat_agent`, `deep_research_agent` and `app._safe_reset` were all reading `_HOST`/`OLLAMA_HOST` directly. `rerank._model_params()` sets `split_mode = NONE` + `main_gpu`; because the emptiest card wins, the reranker lands on the *other* GPU from the Ollama daemon with no coordination. Three traps, each a debugging round-trip: **`CUDA_VISIBLE_DEVICES` alone silently fails for Ollama** — it offers every card through CUDA *and* Vulkan, so a CUDA-hidden card reappears as a Vulkan device and loads there anyway (`OLLAMA_VULKAN=0` fixes it); **CUDA orders devices fastest-first**, so `CUDA_DEVICE_ORDER=PCI_BUS_ID` is required for index N to mean nvidia-smi's GPU N; and **the model store must be picked by manifest count, not existence** — `~/.ollama/models` exists but is empty here while all 51 models live in the system daemon's store. Placement is also a *stability* fix: a split compute graph is what trips the `GGML_SCHED_MAX_SPLIT_INPUTS` assert during ingest. Fails open throughout — remote `OLLAMA_HOST`, `OLLAMA_PIN_GPU=off`, models too big for one card, no `ollama` binary, or a port that never comes up all return the configured host unchanged; an already-serving pinned port is *adopted*, not duplicated. Sidebar shows which branch ran. New `OLLAMA_PIN_GPU` / `OLLAMA_PIN_PORT` / `RERANK_PIN_GPU` (note `"0"` names GPU 0, it is not an off-switch). Verified end-to-end: 167 tok/s on the pinned daemon with GPU0 flat at baseline throughout, VRAM released and no stray daemon after shutdown. 39 new tests (suite 490 passing; the 3 `test_file_processor` failures remain pre-existing).
