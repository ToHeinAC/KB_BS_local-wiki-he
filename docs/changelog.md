| 2026-07-08 | **Language pinning (Layer 1) — deterministic DE/EN preservation.** Fixes drift where a German source could yield an English page summary, and a German (or English) chat/research query could be answered in the other language. New `src/lang.py` (no external deps, imports only `prompts`): `detect(text, default="de")` classifies DE/EN via an umlaut/ß + function-word heuristic robust down to short chat queries (ties/no-signal → German); `response_directive`/`ingest_directive` return the matching **native-language** directive constant. New `prompts.RESPONSE_LANGUAGE_DIRECTIVE`/`INGEST_LANGUAGE_DIRECTIVE` maps (per-language strings written *in* the target language — the strongest steering lever for `gemma4:e4b`). Wiring: ingest pins the **source** language by appending the directive to the ingest **system prompt** (`ingest_begin`; system slot survives the mid-prompt truncation of the 40 KB piece, unlike the tail); wiki-chat `query_with_sources` pins the **query** language in `ANSWER_PROMPT`; `agent.py`/`chat_agent.py` pin it in the system prompt + budget nudge + stall fallback. Structural `## Key facts`, citations, `§`/`#` markers, and numbers are directive-exempt (the directive says so, so the small model keeps them verbatim and the pipeline's heading key still matches). No new LLM calls — cost is code-side detection (µs) + ~100 directive tokens/call; the only material latency is the intended, denser-tokenizing German output when drift is corrected. All new params default to `""` (backward-compatible). New `tests/test_lang.py` (11) + a `test_wiki_engine` ingest-system-prompt assertion; suite 255 passing (3 unrelated pre-existing `test_file_processor` failures remain). AGENTS.md §5.3 gains the hard-rule "Language pinning is code-detected, not model-guessed." |
| 2026-07-08 | **Multi-file (batch) ingest with auto-detected, per-file-editable effective date.** The Upload page ingests **many files at once** — filling a 5-field metadata form per file was impractical. Analysis showed only `effective as of` carries algorithmic weight (feeds `_is_newer` → `_contradiction_check`: "newer supersedes older" vs "unresolved / confidence low"); `name`/`fullname`/`description`/`part of` are cosmetic frontmatter or a title-hint the LLM already derives from content, and routing/identity are content/filename-driven. New `src/metadata_extract.py` (regex-only, no LLM — small-model-safe like `lang.py`/`okf.py`): `extract_effective_date(text)` scans the document head for German/legal vintage cues (`in Kraft getreten`, `gültig ab`, `Stand:`, `Fassung vom`, `vom …`, ISO) and normalizes `TT.MM.JJJJ` / `TT. Monat JJJJ` / ISO → the `YYYY-MM-DD` shape `_parse_date` accepts, else `None`. `src/app.py` Upload rewritten: `st.file_uploader(accept_multiple_files=True)`; a cached (keyed by the set of SHAs) prepare pass dedups, converts non-Markdown via `md_convert`, extracts text, and auto-detects the date per file; a `st.data_editor` review table shows every file with its **editable** detected `effective as of`; an "Apply to all" expander supplies optional shared `part of`/`description`; the confirm dialog is generalized to N files. Batch ingest orders files oldest-first (so `_is_newer` resolves batch-internal contradictions), runs `ingest_begin`/`ingest_piece`/`ingest_end` per file with per-file `try/except` (one bad file doesn't abort the batch), and defers the corpus-wide index build via the new `wiki_engine.ingest_end(ctx, finalize=…)` param — `finalize=False` for every file except the last skips `lex_index.build()` + `update_description()` (still runs the cheap `_rebuild_index()` + log so later files route against earlier ones); a fallback `rebuild_lex_index()` covers the last-file-failed case. Single-file converted-Markdown review retained. Orphaned `template_loader` import removed from `app.py` (module + `templates/insert.md` now unused). New `tests/test_metadata_extract.py` (10) + 4 `test_wiki_engine` tests (finalize deferral ×2, contradiction resolves-with-date / unresolved-without ×2); suite 269 passing (3 unrelated pre-existing `test_file_processor` failures remain). |
| 2026-07-16 | **Link-aware retrieval across both chat modes + Research save/websearch UX.** Question raised: how does the wiki find *connected* data, and can agents follow references? Audit found they largely could not — `linked_pages` (the only link consumer) was wired into the research agent's `wiki_search` alone; Fast chat ignored the graph entirely and Deep chat had no wiki tools at all, so neither chat mode could follow a `related:` reference. Three fixes, all deterministic in code (small-model-safe, no prompt reliance): **(1) undirected traversal** — `related:` is LLM-written at ingest, so pages only cite pages that already existed and ~88% of real edges are one-way (Strahlenschutz: 102 pairs, 12 mutual); following out-links alone made the oldest, most central hub pages look like dead ends. New `_backlink_map()` reverses `build_link_graph()` so in-links count too. **(2) Fast-chat link expansion** — `_candidate_pages_for_query` appends the 1-hop neighbours of the top `_QUERY_LINK_SEEDS`=3 BM25 hits (`_QUERY_LINK_NEIGHBOURS`=3) before the LLM re-rank; BM25 hits keep priority and the ≤5-page cap still bounds synthesis. **(3) implicit shared-source edges** — `_shared_source_siblings()` links pages distilled from a common `sources:` entry (`kind: "shared-source"`), clique-guarded at `_SHARED_SOURCE_MAX_CLIQUE`=8 since a source backing 25 pages (`StrlSchG.md`) carries no topical signal; explicit links outrank shared-source siblings in the ranking. Measured neighbour reach (out-links-only → new): Strahlenschutz 153→220, Investing 37→166, KI 77→298 (all 44 KI pages now reach a neighbour, up from 26). **Deep chat may now read the wiki**: `wiki_search`/`wiki_read` added to `CHAT_TOOLS` — the wiki is the *map* (find which originals matter, follow cross-references), `data/raw/` stays the *territory*. Enforced in code, not prose: `_submit_chat_impl` counts `[Wiki: page.md]` toward `CHAT_MIN_SOURCES` but rejects any answer citing no `[Source: ...]` original; `chat_agent._cites` splits `sources`/`wiki_sources` onto the UI's Documents/Wiki-pages panels. Removed the now-contradictory "MUST be the first non-think tool call" claims from the shared `WIKI_SEARCH_DESCRIPTION`/`RAW_SEARCH_DESCRIPTION` (both system prompts already own tool ordering, and the two tools are bound to both agents). **Research page**: states up front that research mode includes web search; the always-on "Auto-save to wiki" checkbox is replaced by an explicit "Save to wiki" button on the result (also works on the fallback path where the agent answers without filing a report). +11 tests. |
